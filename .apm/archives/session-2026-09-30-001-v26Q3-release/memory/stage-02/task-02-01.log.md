# Task 2.1 - Startup Ops and Timezone Config

## Summary
Added a single-instance PID lock and an ffmpeg-on-PATH startup probe to
`teamode.py`, and added `TEAMODE_TIMEZONE` parsing (IANA name via
`zoneinfo.ZoneInfo`, with fallback to `DEFAULT_TIMEZONE` and then UTC) to
`app/config.py`.

## Details
- `app/pidlock.py` (new, no `discord` import, path-parameterized functions
  so tests use `tmp_path`): `is_pid_alive`, `read_pid`, `write_pid`,
  `remove_pid_file`, `acquire_pid_lock`. `acquire_pid_lock` logs ERROR and
  raises `SystemExit(1)` when the file holds a live PID, otherwise writes
  the current PID (overwriting a stale/absent one) and registers
  `remove_pid_file` via `atexit.register`. `remove_pid_file` only deletes
  the file if it still holds the PID that registered the cleanup (safety
  against deleting a newer instance's lock).
- `teamode.py`: `main()` now calls `acquire_pid_lock(PID_FILE_PATH)` then
  `check_ffmpeg()` before `db.init_db`. `check_ffmpeg()` and the constant
  `FFMPEG_MISSING_WARNING` live in `teamode.py` itself (kept local since
  it's log output, not Discord-facing copy — consistent with "your
  choice, be consistent" in the Task Prompt).
- `app/config.py`: added `_load_timezone(raw_tz: str) -> tzinfo` and
  module-level `TEAMODE_TIMEZONE: tzinfo`. Empty/unset env var uses
  `DEFAULT_TIMEZONE` from `app/constants.py` directly (no warning — this
  is the documented default, not an error). Invalid name (either
  `ZoneInfoNotFoundError` or `ValueError` for malformed keys) logs a
  WARNING with the offending value and falls back to `DEFAULT_TIMEZONE`;
  if that also fails to resolve, logs a second WARNING and falls back to
  `datetime.timezone.utc`. `app/config.py` imports `app.constants`, not
  the other way around, per the constraint.
- `.env.example`: appended `TEAMODE_TIMEZONE=America/Los_Angeles` stub
  line, matching existing style (plain `KEY=value`, no quotes).
