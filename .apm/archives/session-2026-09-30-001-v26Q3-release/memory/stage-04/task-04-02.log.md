# Task 4.2 - /teamode-clear

## Summary
Implemented `/teamode-clear` end to end: a pure classifier module, the
command handler with protected-ID logic, and full unit + bot-level test
coverage. Full validation pipeline is clean. Returning Partial only
because completion requires a manual Discord smoke test per the
Approval Workflow / Validation Protocol.

## Details
1. Read `app/constants.py` (via `git show HEAD:...`), `app/discord_bot/client.py`,
   `commands.py`, `views.py`, `breaks.py`, `lifecycle.py`, `timer.py`,
   `app/session.py`, and the two referenced test files for fixture/patching
   patterns, per the Integration Steps.
2. Built `app/cleanup.py`: no `discord` import. `_template_pattern()` turns
   a `str.format` template into a full-match regex (literal parts escaped,
   each `{field}` → non-greedy `.*?`, `re.DOTALL` so a placeholder can
   swallow embedded newlines) using `string.Formatter().parse`. Every
   matcher is built from `app.constants` values — no duplicated literals.
   `is_delete_eligible(*, content, embed_titles)` checks timer messages
   first (never eligible, so nothing else can shadow them), then handoff
   notices (never eligible), then each delete-eligible category from the
   Task Prompt.
3. Built `app/discord_bot/clear.py` as a new `ClearMixin` (chose the new
   mixin over growing `commands.py`, per the Task Prompt's stated option —
   `commands.py` was already 369 lines and this is a self-contained
   concern). Registers `teamode-clear` on `self.tree`. `_protected_message_ids`
   uses `registry.find_active_in_text_channel` (a FOLLOWUP session is
   non-terminal, so this single call also covers "live Reflect awaiting
   ✅/⛔" — no separate FOLLOWUP-state branch needed) to gather the
   session's timer/setup/Reflect ids, plus `_channel_cleanup[channel_id]`
   while that session exists (covers the case where a live follow-up's
   Time's up id is only reachable via `_channel_cleanup`), plus the
   channel's live chain-prompt and break-message ids. `_handle_clear`
   checks `interaction.permissions.manage_messages` (confirmed via
   `inspect.getsource` that this discord.py 2.7.1 property always returns
   a `Permissions` object, never `None`, so no null-check is needed —
   noted here since the Task Prompt didn't specify this), narrows the
   channel to `VoiceChannel | TextChannel`, defers ephemeral+thinking,
   iterates `channel.history(limit=CLEAR_SCAN_LIMIT)`, skips non-bot
   authors via `message.author.bot`, skips protected ids, classifies via
   `app.cleanup.is_delete_eligible`, deletes one at a time with
   individual `NotFound`/`Forbidden`/`HTTPException` handling logged at
   WARNING, clears any matching `_channel_cleanup` field on successful
   delete, and replies with `CLEAR_DONE`/`CLEAR_NOTHING`.
4. Wired `ClearMixin` into `TeaModeBot`'s MRO in `client.py` and added
   `self._register_clear_command()` alongside the existing
   `self._register_command()` call.
5. Wrote `tests/test_cleanup.py` (26 tests: every delete-eligible fixture
   built by formatting the real constants, every kept fixture including
   all four timer durations and the solo-grace content on a timer embed).
6. Wrote `tests/test_bot_clear.py` (16 tests): permission refusal + no
   scan, wrong-channel refusal, `history(limit=CLEAR_SCAN_LIMIT)` call,
   ephemeral+thinking defer, non-bot messages kept, a full active session's
   timer/welcome/Set-Intention/nudge kept, a live FOLLOWUP session's
   Reflect kept, all three chain-prompt kinds kept (parametrized), a live
   break kept, a handoff notice kept, eligible past messages deleted and
   counted, `CLEAR_NOTHING` reply, one delete raising `NotFound` logged at
   WARNING with the rest still deleted, and `_channel_cleanup` fields
   cleared for deleted ids.
7. Ran the full validation pipeline (see Validation below) and fixed
   formatting via `ruff format` on only the new/changed non-constants
   files (never touched `app/constants.py`).
8. Committed on `feat/teamode-clear` (commit `f12ddeb`), staging files
   explicitly by path; `app/constants.py` was never staged (confirmed
   `git diff --stat app/constants.py` still shows the User's uncommitted
   smoke edits after the pytest-against-committed-constants step).

**In-Discord checklist** (the new `/teamode-clear` command appears after
the bot syncs commands on startup):

1. Run a couple of short `/teamode` sessions to completion in a voice
   channel's text chat — include at least one ⛔ answer (to generate a
   "why" line), one break (to generate `BREAK_STARTED`/`BREAK_OVER`), and
   optionally one expired welcome (let a `/teamode` invocation sit past
   `PENDING_TIMEOUT_SECONDS` without picking a duration) if convenient.
2. Start one more `/teamode` session and leave it running (welcome or
   active timer — either state works).
3. Run `/teamode-clear` as a user **with** the Manage Messages permission.
   Confirm:
   - All timer messages and handoff notices (if any occurred) remain.
   - The running session's welcome / Set Intention / timer message(s)
     remain untouched.
   - Past welcomes, Set Intention prompts, Time's up messages, Reflect
     messages, ⛔ why-lines, wrap-up nudges, chain prompts, and break
     messages from the completed sessions are gone.
   - The ephemeral reply reads `🧹 Cleared N messages.` with the correct
     count.
4. Run `/teamode-clear` again immediately — confirm the ephemeral reply
   reads `Nothing to clear.`
5. Run `/teamode-clear` as a user **without** Manage Messages — confirm
   the ephemeral refusal `You need the Manage Messages permission to run
   /teamode-clear.`
