# Task 4.3 - Break Refinements

## Summary
Implemented per-channel streak tracking with a long-break offer, and voice
join + status during breaks (start and end) with disconnect-on-cancel. All
automated validation passes (264 tests, ruff, pyright, injection scan).
Returning Partial for the User's manual Discord re-check per the task's
checkpoint requirement.

## Details

### Streak tracking and the long-break offer
- `TeaModeBot.__init__` (`app/discord_bot/client.py`) gained two new
  in-memory dicts: `_streaks: dict[int, list[int]]` (channel_id → list of
  qualifying session durations) and `_chained_via_go_again: dict[int,
  bool]` (session_id → whether that session was started via Go again).
- `CommandsMixin._start_session` (`app/discord_bot/commands.py`) now takes
  `via_go_again: bool = False`. It records the flag against the new
  session and, when `via_go_again` is `False` (a plain `/teamode` start),
  calls the new `BreakMixin._reset_streak(channel_id)` to restart the
  channel's streak from scratch. `BreakMixin._handle_go_again` passes
  `via_go_again=True`.
- `BreakMixin._post_chain_prompt` (`app/discord_bot/breaks.py`) now does
  the streak bookkeeping before deciding which prompt to post: it pops the
  chained flag (`_pop_chained_flag`), and if the session was **not**
  chained, clears any existing streak first (so a plain `/teamode` session
  or a Go-again session that broke from a prior streak starts fresh); if
  the session **qualifies** (`duration_minutes >=
  LONG_BREAK_MIN_SESSION_MINUTES`) it appends the duration to the (now
  possibly-fresh) streak; otherwise the streak is cleared outright. This
  single sequence gives the exact reset/extend semantics from the Task
  Prompt in one pass — see the module docstring in `breaks.py` for the
  full explanation. Once the resulting streak reaches
  `LONG_BREAK_STREAK` entries, it posts `CHAIN_PROMPT_STREAK` (Go again +
  `BUTTON_LONG_BREAK`, custom_id `teamode:<sid>:break:long`) instead of
  the normal `CHAIN_PROMPT`; the `_ChainState.kind` literal gained a third
  value, `"chain_streak"`, so `_disable_chain_message` rebuilds the right
  button row.
- `BreakMixin._handle_break` reads an optional 4th custom_id segment
  (`"long"`) to pick `LONG_BREAK_MINUTES` vs `BREAK_MINUTES`, and always
  calls `_reset_streak` for the channel (any break — long or short —
  clears the streak).
- Streak/chained-flag resets were also added at every other cancellation
  path named in the Task Prompt: the follow-up-timeout watchdog and the
  solo-grace timeout in `app/discord_bot/lifecycle.py` (both look up the
  session's `text_channel_id` before/while it's still in the registry),
  the pending-expiry watchdog (`_run_pending_expiry`), and the
  voice-connect-failure branch of `IntentionModal.on_submit`
  (`app/discord_bot/views.py`) — added `_reset_streak`/`_pop_chained_flag`
  to the `_ModalBot` Protocol and to `ViewsMixin`'s `TYPE_CHECKING` stubs
  so it type-checks without a cast.

### Voice during breaks
- `_BreakState` gained `voice_client: discord.VoiceClient | None = None`.
- `_handle_break` now connects to the voice channel right after posting
  `BREAK_STARTED`; on success it calls `_set_voice_status(channel,
  VOICE_STATUS_BREAK.format(hhmm=<break end>))`. A connect failure is
  logged at WARNING and the break continues with no status (matches the
  Task Prompt's explicit allowance).
- `_run_break` gained `break_minutes: int = BREAK_MINUTES` and
  `voice_client: discord.VoiceClient | None = None` parameters (both
  default so the existing direct-call test signature keeps working). At
  break end: if the passed-in client is `None` or no longer connected, it
  reconnects (same behavior as before this Task, for the connect-failed-
  at-start case); it then sets `VOICE_STATUS_BREAK_OVER` **before** calling
  `voice.play_reverie_then_disconnect`, matching the required ordering.
- `BreakMixin._cancel_break` now disconnects the break's stored voice
  client (`voice.disconnect`, WARNING on failure) before editing the break
  message to `BREAK_CANCELLED`; no status is set on cancel, per the Task
  Prompt (the new session's own Timer status overwrites it once it
  activates).

## Important Findings
- **`/teamode-clear` Task dependency**: `_ChainState.kind` now has three
  values — `"chain"`, `"chain_streak"`, `"post_break"` — where it
  previously had two. Any future Task that inspects chain-state kinds to
  decide whether a message is a "live" chain/break prompt (e.g. to skip
  it during a channel clear) needs to treat `"chain_streak"` the same as
  `"chain"` (both are live prompts with distinguishable button rows via
  `_build_chain_view` / `_build_streak_chain_view`).
- **`_BreakState.voice_client`**: the dataclass gained a new field
  (`voice_client: discord.VoiceClient | None = None`, defaulted for
  backward compatibility). Any future code that constructs or reads
  `_BreakState` should be aware this field now exists and is the
  authoritative handle for the break's voice connection — `_cancel_break`
  disconnects it, and `_run_break` reuses it at break end when still
  connected.
- **Streak state is per bot-instance, in-memory** — like every other
  chain/break state, it does not survive a restart. A restart mid-streak
  silently drops back to "no streak," which is accepted per the Task
  Prompt but worth noting for anyone debugging a "missing" long-break
  offer after a bot restart.
