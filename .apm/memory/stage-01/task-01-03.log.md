# Task 1.3 - Constants Module

## Summary
Created `app/constants.py` holding every tunable number, palette value, and
Discord-facing string; refactored `app/discord_bot/` to read from it; added
duration-pick validation against `DURATIONS_MINUTES`. Full pipeline is clean
and all tests pass (125, up from 122).

## Details
1. Read all of `app/discord_bot/` (`client.py`, `commands.py`, `views.py`,
   `timer.py`, `lifecycle.py`), `pyproject.toml`, and the tests that import
   module-level names, per the dependency context.
2. Inventoried every Discord-facing string and tunable, going beyond the
   Task Prompt's explicit list once the code made more surface visible (see
   Important Findings) — including the `/handoff` guard refusals and
   announcement, the automatic (voice-leave) handoff announcement, the
   "Time's up" / no-mention variants, the Reflect embed, the follow-up "why"
   prompt, and the welcome embed / intention modal copy.
3. Built `app/constants.py` in four commented sections: tunables, palette,
   existing copy (grouped by surface: invocation guard, handoff,
   welcome/timer view, intention modal/active timer, end-of-session), and
   new copy (voice status, timer embed, chaining/breaks, refusals/nudge,
   stats, clear, `TEACUP_BANNER`) — all verbatim from the Task Prompt.
4. Consolidated the duplicated Set-Intention prompt into one
   `MSG_PARTICIPANT_PROMPT` template with a `{mentions}` placeholder that is
   `""` (no members) or `"<mention> <mention> "` (members, trailing space) —
   verified byte-for-byte against both original call-site outputs before
   consolidating.
5. Rewired `commands.py`, `views.py`, `timer.py`, `lifecycle.py` to import
   from `app.constants` and removed every old module-level `_MSG_*` /
   `_*_SECONDS` / `_ACTIVE_TIMER_FMT` / `_END_EMBED_*` / `_BACKOFF_*`
   definition. `COLORS` in `views.py` now builds `discord.Color` objects from
   the new `COLOR_*` hex constants in `app.constants`; keys/semantics
   unchanged.
6. Fixed while moving: `_build_timer_view`'s stale "10 / 25 / 50" docstring
   (now generic, since the source of truth is `DURATIONS_MINUTES`), and the
   inaccurate "two spaces between intention and timer" comment on the timer
   format (the format is newline-separated, not space-separated) — replaced
   with an accurate comment.
7. Added the duration-pick guard in `ViewsMixin._handle_timer_pick`: if the
   parsed `duration_minutes` is not in `DURATIONS_MINUTES`, reply with the
   `MSG_SESSION_INACTIVE` ephemeral refusal and return before `set_duration`
   is called — no modal, no state change.
8. Updated test imports (`test_bot_followup.py`, `test_bot_intention.py`,
   `test_bot_invocation.py`, `test_bot_tick_callback.py`) to import the
   renamed public constants from `app.constants`; no behavioral assertion
   changed except `MSG_PARTICIPANT_PROMPT.format(mentions="")` replacing the
   old direct equality check (same value).
9. Added `tests/test_constants.py`: an AST-based check that
   `app/constants.py` imports neither `discord`, `app.config`, nor
   `app.discord_bot`; and an exact-lines/leading-spaces check for
   `TEACUP_BANNER`.
10. Added `test_invalid_duration_click_sends_refusal` in
    `test_bot_intention.py` proving a `teamode:<id>:timer:7` custom_id gets
    the `MSG_SESSION_INACTIVE` refusal and does not advance the session.
11. Ran the full validation pipeline (ruff format --check, ruff check,
    pytest, pyright, scan_injection.sh) — all clean.

## Important Findings
- The inventory of Discord-facing strings was substantially larger than the
  Task Prompt's explicit list: it named the `/handoff` refusals and
  announcement copy only implicitly ("handoff announcements", "/handoff
  refusals"), and did not mention the automatic (voice-leave) handoff
  announcement, the "Time's up[, @mentions]!" pair, the Reflect embed
  title/description, or the follow-up "why" prompt at all. All of these are
  now in `app/constants.py` under "Existing copy" so Task 1.4 (and later
  Tasks touching this surface) find a complete inventory rather than a
  partial one.
- While consolidating the participant prompt, I initially added
  `isinstance(channel, discord.abc.Messageable)` narrowing in
  `lifecycle.py` (to touch the follow-up "why" prompt and auto-handoff
  announcement lines while moving their strings to constants). This broke
  no test locally in a quick check, but on inspection the existing tests
  pass plain unspec'd `AsyncMock()`/`MagicMock()` objects as the channel,
  and `isinstance(AsyncMock(), discord.abc.Messageable)` is `False` at
  runtime (confirmed via a quick REPL check) — so that narrowing would have
  silently broken the auto-handoff-announcement and follow-up-why-prompt
  tests. I reverted those two spots to their original `cast(...)` /
  `# type: ignore[union-attr]` form (string constants only, no typing
  change) so Task 1.4 handles the cast removal with full context on how
  those specific tests build their fake channel objects — flagging this so
  Task 1.4 does not fall into the same trap by re-introducing that
  isinstance narrowing without updating (or checking) those fixtures first.
