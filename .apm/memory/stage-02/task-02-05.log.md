# Task 2.5 - Setup-Flow Refinements

## Summary
Duration can now be re-picked until the intention modal is actually
submitted (buttons disable on submit, not on pick); a second submit for a
non-PENDING session is refused; and the next `/teamode` in a text channel
now also deletes the previous ⛔ "why" line and strips the embed from the
previous Reflect message, alongside the existing Time's-up deletion. All
automated validation is clean. Status is Partial only because step 9
requires the User's manual Discord smoke re-check.

## Details
- **`app/discord_bot/views.py`**
  - `_handle_timer_pick`: removed the `View.from_message` + `message.edit`
    block that disabled the welcome's duration buttons on the first pick.
    A pick now only records the duration (`set_duration`) and opens the
    modal; the pending-expiry watchdog stays armed as before. A second pick
    for the same still-PENDING session re-records the new duration and
    opens a fresh modal (latest pick wins — `set_duration` already
    overwrites, no registry change needed).
  - `IntentionModal.on_submit`: added a double-submit guard at the very
    top — `self._bot._registry.get(...)` + `_session_actionable(...,
    expect=SessionState.PENDING)`; a miss sends the ephemeral
    `MSG_SESSION_INACTIVE` refusal (via the existing `_send_refusal`
    helper) and returns before `set_intention`, voice connect, or the
    timer send. Noted per the Task's guidance: because `set_intention` is
    synchronous and transitions the session before any `await`, this
    single check before that call is sufficient under asyncio's
    cooperative scheduling — no interleaving is possible.
  - After `set_intention` succeeds and the interaction is deferred, added
    a best-effort edit of the welcome message (via
    `self._voice_channel.get_partial_message(setup.welcome_message_id)`,
    the channel captured at click-handler time, never the interaction
    webhook) to `_build_timer_view(session_id, disabled=True)`. Guarded by
    `setup is not None` (the lookup in `self._bot._setup_messages`);
    failures (`NotFound`/`Forbidden`/`HTTPException`) are logged at
    WARNING and do not block voice connect / `mark_active` below.
  - Added `_setup_messages: dict[int, _SetupMessages]` to both `_ModalBot`
    (Protocol) and `ViewsMixin`'s declared attributes, since the new
    welcome-disable step needs it and `ViewsMixin` must structurally
    satisfy `_ModalBot` for the existing `self` pass-through to
    `IntentionModal`.
  - Added `_ChannelCleanup` dataclass (`times_up_id`, `reflect_id`,
    `why_id`, all `int | None = None`) next to `_SetupMessages`, replacing
    the bare `_last_end_message_ids: dict[int, int]`.

- **`app/discord_bot/client.py`**: `TeaModeBot.__init__` now holds
  `self._channel_cleanup: dict[int, _ChannelCleanup] = {}` in place of
  `_last_end_message_ids`.

- **`app/discord_bot/lifecycle.py`**:
  - `_run_end_of_session`: records `times_up_id` into the channel's
    `_ChannelCleanup` entry (created via `setdefault`) when the Time's-up
    message is sent, and `reflect_id` when the Reflect message is sent
    (alongside the existing `self._reflect_message_ids[session_id]`).
  - `on_raw_reaction_add` (⛔ branch): captures the `FOLLOWUP_WHY_PROMPT`
    message's id (from the `channel.send` return, per convention) into the
    channel's `_ChannelCleanup.why_id`.

- **`app/discord_bot/commands.py`** (`_start_session`): replaced the
  single Time's-up pop/delete with popping the whole `_ChannelCleanup`
  entry for the channel and handling each of `times_up_id` (delete),
  `why_id` (delete), and `reflect_id` (edit with `embed=None`, leaving
  `content` untouched — confirmed against the installed discord.py 2.7.1
  `PartialMessage.edit` signature, `.venv/lib/python3.12/site-packages/discord/message.py:2868`,
  where `content` defaults to `MISSING` and is left alone). Each step is
  independent: a failure is logged at WARNING with a distinct message per
  step and does not block the others or the new session.
