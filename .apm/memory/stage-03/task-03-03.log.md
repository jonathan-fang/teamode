## Summary
Pluralized the wrap-up nudge, added a non-blocking wind chime played alongside it, tracked and deleted the nudge message at terminal cleanup, and appended "remaining" to the timer content line. Full validation pipeline is clean (223 tests, 0 ruff/pyright errors). Returning Partial per the Task Prompt's required User re-check (manual Discord smoke test).

## Details
- `app/constants.py`: added `MSG_WRAP_UP_NUDGE_ONE = "⏰ Wrap-up nudge — 1 minute left."` next to `MSG_WRAP_UP_NUDGE` (commented as used for 2+ minutes); changed `TIMER_CONTENT` to `"⏳ {mmss} remaining"`.
- `app/timer_format.py`: added `format_wrap_up_nudge(minutes: int) -> str` — returns `MSG_WRAP_UP_NUDGE_ONE` for `minutes == 1`, else `MSG_WRAP_UP_NUDGE.format(minutes=minutes)`.
- `app/voice.py`: added `WIND_CHIME_PATH` (same construction as `REVERIE_PATH`) and `play_wind_chime(voice_client) -> bool` — refuses (WARNING, returns `False`) when not connected or already playing, catches `discord.ClientException` / `OSError` from `play()`, never awaits completion, never disconnects.
- `app/discord_bot/views.py`: added `nudge_message_id: int | None = None` to `_SetupMessages`.
- `app/discord_bot/timer.py` (`TimerMixin._on_countdown_tick`): nudge branch now calls `timer_format.format_wrap_up_nudge(WRAP_UP_MINUTES)`, stashes the sent message's id on `self._setup_messages[session_id].nudge_message_id` (only if the send succeeded and a `_SetupMessages` entry exists), then calls `voice.play_wind_chime` on `self._voice_clients.get(session_id)` regardless of whether the nudge send succeeded; missing voice client logs a WARNING and is skipped. Declared `_setup_messages` and `_voice_clients` as mixin attributes.
- `app/discord_bot/lifecycle.py` (`LifecycleMixin._on_session_terminal`): the setup-message deletion loop now also deletes `setup.nudge_message_id` (via the channel partial message, same WARNING handling as the others). Docstring updated. Pending expiry (`delete_setup_messages=False`) is unaffected — no nudge message exists at that point.
- `docs/discord-bot-setup.md`: updated the one literal example of the old `⏳ MM:SS` content to `⏳ MM:SS remaining` for consistency (this doc is tracked, unmodified before this Task, not one of the User's own in-flight edit files).
- Verified via `.venv/lib/python3.12/site-packages/discord/player.py`: `FFmpegPCMAudio`'s `Popen` failure (e.g. ffmpeg missing) already raises `discord.ClientException` (not a bare `FileNotFoundError`), so catching `ClientException` covers the missing-ffmpeg case; `OSError` is kept as defensive belt-and-suspenders per the Task Prompt.
- No existing test asserted the old bare `⏳ {mmss}` content literal — `tests/test_bot_tick_callback.py` and `tests/test_bot_intention.py` both build their expectation via `TIMER_CONTENT.format(mmss=...)`, so they picked up the new copy automatically; no edits needed there beyond the new tests added.
