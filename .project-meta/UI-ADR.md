# UI Architecture Decision Record — TeaMode

Current Discord-surface state for TeaMode (Ocha bot). Reference this
document instead of re-reading the codebase when making UI decisions per
`.LLMAO/ui-decisions-subsection.md`.

**`app/constants.py` is the source of truth for every string quoted
below.** This document is a reading aid over that file, not a
replacement for it — if the two ever disagree, `app/constants.py` wins
and this file needs a re-sync.

Last reviewed: 2026-09-30 (post `v26Q3.0.0.0` — reflects landed code).

---

## Bot identity

- **Application name** (Discord developer portal, internal): `TeaMode`.
  Matches the repo (CamelCase reading) for searchability while the
  slash commands stay lowercase per Discord convention.
- **Bot user display name** (what people see in chat): `Ocha`.
  Short, mentionable (`@Ocha`), tea-coded, distinct from the application
  name. The asymmetry is intentional — the application is the project,
  Ocha is the persona.
- **Avatar / icon / banner:** generated by `scripts/generate_art.py`
  (dev-only, see README § "Art assets"); a person picks and uploads the
  finals in the Developer Portal. Shipped finals: `assets/app-icon.png`,
  `assets/app-banner.png`, `assets/app-avatar.png` — a flat teacup with
  steam on an amber saucer, pale-sage ground.

## Emoji palette

The consistent pair: **🍵** (tea moments — welcome, expiry) and
**⏳** (active timer, timer voice status). Secondary emoji used
sparingly:
- 🌿 — accent on success / "kept your intention" / Reflect embed
- ✨ — small flourish on session completion / voice status "Done"
- 🥅 — accent on goal-setting (`[Set Intention]` prompt)
- ⏰ — wrap-up nudge
- ⏸️ — break started / break voice status
- 🧹 — `/teamode-clear` completion
- 🔥 — stats streak line
- ✅ / ⛔ — follow-up reactions on the Reflect-embed message.
  Pre-populated by the bot. The current facilitator's reaction is
  **authoritative** for `completed_intention` (✅ = 1, ⛔ = 0). Other
  participants' reactions are logged-only social signal.

Do not introduce new emoji without updating this section.

### Welcome embed copy (canonical)

- **Title:** `🍵 Now Entering TeaMode` (`WELCOME_EMBED_TITLE`)
- **Description** (`WELCOME_BANNER_BLOCK` + `WELCOME_EMBED_DESCRIPTION`,
  each body line prefixed `### ` for heading-style weight):

> ```
> {TEACUP_BANNER}
> ```
> ### Time for TeaMode!
> ### · Grab your tea (or water/beverage of your choice),
> ### · Clear your desk,
> ### · And silence all distractions (like phones, impromptu meetings).
>
> ### ⏳ **How long would you like to focus today?**

The ASCII teacup banner (`TEACUP_BANNER`) is the one exception to the
project's no-AI-generated-runtime-text rule — explicitly approved by
the User (see `AGENTS.md` § Execution Constraints).

- **Accent color:** `#7B9D6F` (matcha sage — `COLORS["active"]`).
- **Buttons (attached to the same message):** `{minutes} min` per
  `DURATIONS_MINUTES` (`5 / 10 / 25 / 50`) — secondary style.

### Participant prompt copy (canonical)

`MSG_PARTICIPANT_PROMPT`:

```
🥅 **[Set Intention]** {mentions}Please share your intention for this
session in voice or type it in the chat.
```

`{mentions}` is `""` when the voice channel has no non-bot members, or
`"<mention> <mention> "` (trailing space) otherwise.

### Timer embed copy (canonical)

`TIMER_EMBED_TITLE`: `🍵 TeaMode • {duration} min session`. Fields:

- **Intention** (`TIMER_FIELD_INTENTION`) — the submitted intention, or
  `INTENTION_LINE_UNSET` (`🍵 No intention set`) when blank.
- **Facilitator** (`TIMER_FIELD_FACILITATOR`) — the current
  facilitator's mention.
- **Range** (`TIMER_FIELD_RANGE`) — `TIMER_TIME_RANGE`:
  `{start} to {end}`, `HH:MM` in `TEAMODE_TIMEZONE`.

Body: a phase label (`PHASE_DEEP_FOCUS` = `Deep focus`, switching to
`PHASE_WRAP_UP` = `Wrap up — finish your current task` at
`WRAP_UP_MINUTES` remaining, with the accent color shifting from
matcha sage to oolong amber), `TIMER_REMAINING` (`{mmss} remaining`),
and `TIMER_PROGRESS` (`{bar} {percent}%` — a `PROGRESS_BAR_WIDTH`-wide
unicode bar). If an embed edit fails, the fallback is a plain content
line (`TIMER_CONTENT`: `⏳ {mmss} remaining`).

### Chaining and break copy (canonical)

- Default chain prompt (`CHAIN_PROMPT`): `Go again? / Take a
  5-minute break?` — buttons `BUTTON_GO_AGAIN` (`Go again`) and
  `BUTTON_BREAK` (`Take a 5-minute break`).
- Streak chain prompt (`CHAIN_PROMPT_STREAK`, after
  `LONG_BREAK_STREAK` chained sessions each ≥
  `LONG_BREAK_MIN_SESSION_MINUTES`): `Go again? / Take a 10-minute
  break? You've done {count} sessions in a row ({durations}).` —
  buttons `BUTTON_GO_AGAIN` and `BUTTON_LONG_BREAK` (`Take a 10-minute
  break`). `{durations}` joins `STREAK_DURATION_ITEM` (`{minutes} min`)
  with `STREAK_DURATION_SEPARATOR` (` / `).
- `BREAK_STARTED`: `⏸️ Break started — back at {hhmm}`.
- `BREAK_OVER`: `⏸️ Break is over`.
- `BREAK_CANCELLED`: `⏸️ Break cancelled by /teamode` — shown when
  `/teamode` is invoked during an active break.
- Any voice member (not just the facilitator) may click Go again or
  either break button; a break joins voice silently and ends with the
  reverie chime.

### End-of-session embed copy (canonical)

- **Title:** `✨ Session complete!` (`END_EMBED_TITLE`)
- **Body:** `🌿 Sip your tea, stretch, and notice your progress.`
  (`END_EMBED_BODY`, rendered `### `-prefixed).
- **Accent color:** `#3F5E4A` (steeping forest — `COLORS["end_of_session"]`).
- **Content** (@-mentions of current voice channel members at
  end-tick, Ocha filtered out; mentions ping):

  ```
  Time's up, <@id1> <@id2> <@id3>!
  ```

  If the voice channel is empty, `content` is `"Time's up!"`
  (`END_OF_SESSION_NO_MENTION`) with no mention list.

Posted as a single `channel.send(content=..., embed=...)` call.

### Reflect embed copy (canonical)

- **Content:** `FOLLOWUP_PROMPT` — `[Follow-up] React with ✅ if you
  finished, or ⛔ if not.`
- **Embed title:** `🌿 [Reflect]` (`REFLECT_EMBED_TITLE`)
- **Embed body** (`REFLECT_EMBED_DESCRIPTION`, each line `### `-prefixed):

  > ### Share how your session went!
  > ### · React with emoji
  > ### · Share in voice
  > ### · Or type in chat

- **Accent color:** `#3F5E4A` (steeping forest).

### "Why" prompt copy (canonical)

`FOLLOWUP_WHY_PROMPT`, posted only when the facilitator reacts ⛔:

```
<@{facilitator_id}> — share what got in the way: type in chat or share in voice.
```

The bot does not capture the response (`followup_note` stays NULL).

### `/teamode-stats` surface (canonical)

Ephemeral embed, `STATS_TITLE` (`🍵 TeaMode stats`), accent
`COLORS["active"]`. Two fields:

- `STATS_SECTION_YOU` (`You`) — the original-facilitator credit (a
  handoff target gets no credit; see `docs/sqlite-schema.md` §
  `handoff_facilitator_id`).
- `STATS_SECTION_SERVER` (`This server`).

Each field has a row per `STATS_WINDOWS_DAYS` (7, 30) plus
`STATS_ROW_ALL` (All time): `STATS_ROW_VALUE`
(`{sessions} · {minutes} min · {rate}% completed`, singular
`STATS_SESSIONS_ONE` at 1 session) or `STATS_ROW_VALUE_NO_RATE`
(`— completed`) when the window has no ✅/⛔ answers. Only sessions
that reached follow-up (`completed` / `followup_timeout`) count — see
`docs/sqlite-schema.md`. `STATS_STREAK` (`🔥 Streak: {days} days`,
singular `STATS_STREAK_ONE`) is appended to "You" only when the
personal streak (consecutive local days with a qualifying session) is
≥ 1. `STATS_EMPTY` shown when there is nothing to report.

### `/teamode-clear` surface (canonical)

- `CLEAR_DONE`: `🧹 Cleared {n} messages.`
- `CLEAR_NOTHING`: `Nothing to clear.`
- `CLEAR_NO_PERMISSION`: `You need the Manage Messages permission to
  run /teamode-clear.` — ephemeral refusal when the invoking member
  lacks Manage Messages (the bot itself does not need it).
- Scans the last `CLEAR_SCAN_LIMIT` (800) messages, deletes one at a
  time paced by `CLEAR_DELETE_INTERVAL_SECONDS` (1.0s). Keeps live
  timers, handoff notices, and anything belonging to a live session,
  chain prompt, or break.

### Voice channel status (canonical)

| Phase | Status text | Constant |
|---|---|---|
| Timer running | `⏳ to {hhmm}` | `VOICE_STATUS_TIMER` |
| Timer finished | `✨ Done at {hhmm}` | `VOICE_STATUS_FINISHED` |
| Solo-grace cancellation | `🍵 Cancelled` | `VOICE_STATUS_CANCELLED` |
| Break running | `⏸️ to {hhmm}` | `VOICE_STATUS_BREAK` |
| Break finished | `✨ Break over at {hhmm}` | `VOICE_STATUS_BREAK_OVER` |

Shown **only while Ocha is connected to the voice channel** — status
is not set on a channel Ocha has left. Setting it requires the "Set
Voice Channel Status" permission (Manage Channels is a separate,
stronger permission Discord could alternatively require here; TeaMode
deliberately does not request Manage Channels).

### Refusal / stale-button copy (canonical)

- `MSG_SESSION_INACTIVE` (`This session is no longer active.`) — the
  single, unified refusal for every stale/finished-session component
  click (timer pick, chain buttons, break buttons — anything added
  later routes through the same constant).
- `MSG_SESSION_ACTIVE`, `MSG_WRONG_CHANNEL`, `MSG_NOT_IN_VOICE` — guard
  refusals on `/teamode` invocation.
- `MSG_RATE_LIMIT_USER` (`Per-user rate limit — try again in {seconds}
  seconds.`) and `MSG_RATE_LIMIT_GUILD` (`Daily server limit reached
  ({cap} sessions per day) — resets at midnight.`).
- `MSG_PENDING_EXPIRED` (`🍵 Expired`) — the welcome embed is edited to
  this and its buttons disabled after `PENDING_TIMEOUT_SECONDS` (10
  min) with no duration pick.
- `/handoff` refusals: `MSG_HANDOFF_NO_SESSION`,
  `MSG_HANDOFF_NOT_FACILITATOR`, `MSG_HANDOFF_SELF`,
  `MSG_HANDOFF_TARGET_BOT`, `MSG_HANDOFF_TARGET_NOT_IN_VOICE`.

## Interaction model

### Slash commands
- `/teamode` — no options; timer length is chosen via post-invocation
  buttons so the user sees options in context.
- `/handoff <member>` — one required member option
  (`HANDOFF_MEMBER_DESCRIPTION`).
- `/teamode-stats` — no options.
- `/teamode-clear` — no options.
- **Scope:** guild-scoped registration via `TEAMODE_DEV_GUILD_ID`
  (`on_ready` calls `copy_global_to` + `tree.sync(guild=...)` per
  configured guild id). If unset, registration is skipped entirely
  with a warning — there is no automatic global-registration fallback.

### Custom_id namespace
All component `custom_id` values follow:

```
teamode:<session_id>:<purpose>[:<value>]
```

Examples:
- `teamode:42:timer:25` — pick 25-minute timer for session 42
- `teamode:42:again` — Go again for session 42's chain prompt
- `teamode:42:break` — start a 5-minute break
- `teamode:42:break:long` — start the 10-minute streak break

The session id makes interactions safe across concurrent sessions in
different channels. Follow-up state is captured via ✅/⛔ reactions on
the Reflect embed message, not a custom_id (see § "Authorization
rules" and § "Emoji palette").

### Authorization rules
- Timer pick / intention modal: facilitator only. Other clicks: the
  unified stale-button refusal or `MSG_NOT_FACILITATOR` (`Only the
  facilitator can answer.`) as applicable.
- Follow-up ✅/⛔ reactions on the Reflect-embed message:
  - **The current facilitator's reaction is authoritative.** ✅ →
    `mark_completed(completed_intention=1)`. ⛔ →
    `mark_completed(completed_intention=0)` + posts the public "why"
    prompt (not bookkept).
  - Anyone else's reaction (including the bot's own pre-populated
    reactions) does not change session state.
- Facilitator handoff: automatic on facilitator-leaves-voice
  (`random.choice` over remaining voice members) or manual via
  `/handoff`. The new facilitator becomes the authoritative reactor.
- Go again / break buttons: any current voice channel member may
  click, not just the facilitator — chaining is a group decision.
- `/teamode-clear`: gated on the **invoking member's** Manage Messages
  permission, checked at the top of the command handler.

### Refusal behavior
When `/teamode` is invoked while another session is active in the same
text channel, the response is **ephemeral** (only the invoker sees it),
muted-grey embed: `MSG_SESSION_ACTIVE`. Rate-limit refusals
(`MSG_RATE_LIMIT_USER`, `MSG_RATE_LIMIT_GUILD`) are ephemeral the same
way.

### Timer edit cadence
- Edit the active timer message every `EDIT_INTERVAL_SECONDS` (10s).
- On `discord.HTTPException` (429), exponential backoff with a floor
  of `BACKOFF_FLOOR_DEFAULT` (10s), capped at `BACKOFF_FLOOR_CAP` (60s)
  — the backoff actually gates the next edit attempt, not just the
  retry.
- Skip an edit if the previous one is still in flight (no edit queue
  build-up).

### Messaging lifecycle (edit/delete, not the interaction webhook)
Any message later edited or deleted (welcome, `[Set Intention]`
prompt, timer message, wrap-up nudge) is sent via `channel.send` or has
its id captured, and is edited/deleted through the channel — never the
interaction webhook, since interaction tokens expire after 15 minutes
and sessions outlast that. The welcome, `[Set Intention]`, and wrap-up
nudge messages are deleted at terminal states (not on pending expiry —
an expired welcome is left edited to `🍵 Expired` instead). At the next
session's start, the previous "Time's up" content and the `⛔`
follow-up reaction line are deleted and the Reflect embed is stripped
back to its base content.

## Mobile rendering

- Discord mobile clips embed widths around ~340px.
- Avoid multi-column field layouts; prefer single-column for the timer
  embed (Intention / Facilitator / Range stack vertically).
- The matcha-sage and oolong-amber accents render correctly on both
  light and dark themes.

## Decisions already made (do not revisit)

These are settled architectural choices. New UI work should build on
them, not reconsider them.

- **No accountability picker, no action step** — dropped from the
  original Steps array.
- **Voice channel's own text chat** is the only valid invocation
  channel.
- **Embed timer with a unicode progress bar** shipped in
  `v26Q3.0.0.0` — this supersedes the earlier "plain-text mm:ss is
  MVP; embed + progress bar is v2 polish, do not preempt" note. The
  plain content-only fallback (`TIMER_CONTENT`) only fires when an
  embed edit itself fails.
- **Ephemeral refusals**, not visible-to-channel public ones, when a
  user is unauthorised, rate-limited, or invokes during an active
  session.
- **Bot joins voice at session start**, not late-join at end. Reverie
  reliability outweighs the small cost of holding a voice connection.
- **Confetti analogue** at end-of-session: a single message with a
  small 🍵🌿✨ flourish; no animated cycle.
- **Timer durations**: `5 / 10 / 25 / 50` min. Reaction-only follow-up
  (not a Y/N click) — see § "Authorization rules".
- **Intention modal accepts empty submissions.** Collapses to
  `🍵 No intention set` when empty or whitespace-only.
- **Participant `[Set Intention]` prompt fires post-welcome** (1-second
  beat after the welcome embed), not post-modal-submit.
- **All content-embed body lines prefixed `### ` for consistent
  heading-style weight.** Applies to the welcome, Session-complete, and
  Reflect embeds. Refusal embeds are excluded — plain body text.
- **`/teamode-stats` and `/teamode-clear` are separate commands**, not
  subcommands of `/teamode` — matches the "single command, no
  subcommands" identity while letting each surface its own permission
  model and options.
- **Chaining and breaks are open to any voice member**, not
  facilitator-gated — a group decision, unlike the timer pick.
- **Voice channel status only while connected.** TeaMode does not
  request Manage Channels to set a status on a channel it has left;
  the tradeoff (no "cooldown" status between sessions) is accepted.
- **The teacup ASCII banner (`TEACUP_BANNER`) is AI-generated text**,
  approved by the User as the sole exception to the no-AI-generated
  runtime-text rule (see `AGENTS.md` § Execution Constraints).
